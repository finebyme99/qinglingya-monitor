# 项目协作规则

这是系统问题清零鸭的代码存档，包含Cloudflare Worker、D1、Durable Object Alarm、Pages转接和独立GitHub巡检。业务规则以 docs/BUSINESS_RULES.md 为当前说明，历史记录在 docs/history/，恢复步骤见 docs/OPERATIONS.md。

## 先理解再改动
- 先检查相关代码、配置和已有改动；复用现有模式，不覆盖他人的工作。
- 先复现和定位故障，选择最小改动；不要把推测写成已确认事实。
- src/core.mjs保存AI判断提示词；卡片、台账、回调、告警各自独立。
- 本快照包含已上线的外部群成员按钮修复；本地归档提交不等于再次部署。

## 业务边界
- 正式群只在北京时间周一至周五09:30、13:30、16:00推送；不能临时试发或盲目补发。
- 数据表人工进展优先；不新增第二个进展列，不用AI覆盖人工判断。
- 群内真实成员（含外部企业）可确认解决；保留二次确认、来源、原卡片、原问题及实时群成员校验。
- 关闭异常私信不等于关闭定时任务、健康检查、故障记录或监控心跳。
- 不拿真实业务问题做测试，不发送真实测试私信；有明确授权时才使用专用测试资源。

## 验证
- 本地运行 npm test、npm run check、node --test external-monitor/test/*.test.mjs。
- 测试使用虚构数据、模拟请求和内存数据库；不加载生产凭证或连接真实后台。
- 改动后先运行相关测试；失败定位后重测，通过后不无故反复验证。
- 实际网页、真实账号和发布验证使用Ego Lite的TaskSpace/Page API；每项任务一个TaskSpace，复用页面，完成后 finish({keep:[]})。
- Playwright只用于隔离环境的本地回归，不附着日常浏览器或真实账号。
- 没有真实用户验证时明确覆盖缺口，不能把本地通过说成线上真人已通过。

## 凭证与发布
- 不读取、输出或提交实际密钥；示例文件只能留空或使用虚构值。
- 不提交群消息、员工问题、生产数据库、真实回执、日志、认证文件或浏览器数据。
- 配置包含真实资源标识，仅使用私有仓库存档。
- 推送、合并和生产部署先列明具体操作取得用户确认；用户本次已明确授权的操作不重复询问。
- 不因部署重置业务计划的启用时间，不停掉巡检工作流。
- 只归档允许的项目文件，不复制嵌套.git、全局规则、个人技能目录或生成记忆。
- 不擅自删除原项目、备份、日志、分支或工作树；归档不触发清场。

## 沟通
- 用户不是IT专业人员：先说结果，简洁说明影响、验证证据和待办。
- 区分本地、已提交、已推送、已部署、线上核查和用户反馈。
